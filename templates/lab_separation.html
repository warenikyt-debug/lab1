API Endpoints по лабораториям

LAB2 - Endpoints аутентификации
POST /api/auth/register - Регистрация
POST /api/auth/login - Логин
GET /api/auth/me - Получить профиль
POST /api/auth/refresh - Обновить токены
GET /api/auth/tokens - Список активных токенов
POST /api/auth/logout - Выход
POST /api/auth/out_all - Выход со всех устройств

Итого: 7 endpoints

LAB3 - Endpoints RBAC

Управление ролями (7 endpoints)

GET /api/ref/policy/role - Получить все роли
POST /api/ref/policy/role - Создать роль
PUT /api/ref/policy/role/{id} - Обновить роль
DELETE /api/ref/policy/role/{id} - Удалить роль (hard)
DELETE /api/ref/policy/role/{id}/soft - Удалить роль (soft)
POST /api/ref/policy/role/{id}/restore - Восстановить роль

Управление разрешениями (7 endpoints)

GET /api/ref/policy/permission - Получить все разрешения
POST /api/ref/policy/permission - Создать разрешение
PUT /api/ref/policy/permission/{id} - Обновить разрешение
DELETE /api/ref/policy/permission/{id} - Удалить разрешение (hard)
DELETE /api/ref/policy/permission/{id}/soft - Удалить разрешение (soft)
POST /api/ref/policy/permission/{id}/restore - Восстановить разрешение

Управление ролями пользователя (6 endpoints)

GET /api/ref/user - Получить всех пользователей
GET /api/ref/user/{id}/role - Получить роли пользователя
POST /api/ref/user/{id}/role/{role_id} - Присвоить роль
DELETE /api/ref/user/{id}/role/{role_id} - Удалить роль (hard)
DELETE /api/ref/user/{id}/role/{role_id}/soft - Удалить роль (soft)
POST /api/ref/user/{id}/role/{role_id}/restore - Восстановить роль

Итого: 20 endpoints (7+7+6)

Зависимости между LAB2 и LAB3

LAB2

Основа

  • User модель
  • Authentication (регистрация, логин)
  • JWT токены
  • Middlewares
LAB3

Надстройка на LAB2

  • Role, Permission модели
  • Авторизация (проверка прав)
  • RBAC система
  • Soft Delete

⚠️ Требует LAB2!

Важно: LAB3 полностью зависит от LAB2. Все функции аутентификации из LAB2 используются в LAB3 для проверки токенов и идентификации пользователя.

Основные классы и компоненты

LAB2 - Классы аутентификации
LAB2 
class User(Base):
    id: int
    username: str
    email: str
    password: str (хешированный)
    birthday: str
    created_at: datetime

class AuthService:
    register(username, email, password, birthday)
    login(username, password) -> (access_token, refresh_token)
    verify_password(password, hashed)

class TokenService:
    create_tokens(user_id) -> (access_token, refresh_token)
    verify_token(token) -> payload
    add_to_blacklist(token)
LAB3 - Классы RBAC
LAB3 
class Role(Base):
    id: int
    name: str
    slug: str
    description: str
    deleted_at: datetime (soft delete)
    users: List[User]
    permissions: List[Permission]

class Permission(Base):
    id: int
    name: str
    slug: str
    description: str
    deleted_at: datetime (soft delete)
    roles: List[Role]

class RoleUser(Base):
    id: int
    user_id: int (FK)
    role_id: int (FK)
    deleted_at: datetime (soft delete)

class PermissionService:
    check_permission(user_id, permission_slug) -> bool
    # Проверка цепочки: User -> Role -> Permission

Какие файлы использовать для какой лабораторной

⚠️ Для сдачи LAB2: Используй только файлы с синим выделением (LAB2). LAB3 компоненты должны быть удалены или отключены.
✅ Для сдачи LAB3: Используй файлы LAB2 + файлы LAB3 (все файлы). LAB2 служит основой для LAB3.
